# Meme猫 · 原生桌面版

Tkinter原生窗口绘制GIF/图片，Pillow后台解码/缩放并有界缓存，ALSA播放配套WAV。
**不打开浏览器，不使用WebView。STT在本地离线识别，最终文字按用户要求发送服务器；发送功能需要网络。**沿用上一级播放器的代码、素材编号与`data/assets.sqlite3`，不会重新全量导入素材。

## 在这台树莓派使用

本文件夹应位于 `player/desktop`，同级上方有`launch.py`、`website`和`data`。
已获取的实际检测报告确认：Debian12 ARM64、Python3.11，`python3-tk`、`python3-pil`、`python3-pil.imagetk`、ALSA已安装；无需pip、apt或sudo。

在**树莓派桌面自身的终端**执行：

```sh
sh player/desktop/start.sh
```

默认全屏。底部按钮选择表情、重播、管理和退出，F11切换全屏，Esc退出全屏。
播放画面内仅有表情与底部回复字幕，不显示文件名、素材名、时长或计时。
首次显示原场景“你好呀”；Linux自动收音启动时，首次问候不播放配套声音，避免自动问候回灌麦克风。手动重播仍有原配声音。场景只是人工演示，不是情绪识别结果。

可选创建本人桌面/应用菜单入口（不会加入开机自启）：

```sh
python3 player/desktop/install_shortcut.py
```

以后点击“Meme猫播放器”即可。若系统要求信任快捷方式，请本人按系统提示确认。不要移动player文件夹后继续使用旧快捷方式。

## 素材与回复

- meme素材按目录编号映射，播放带背景GIF与原配WAV；自定义user-素材保留在原数据库。只缓存当前表情的画面，不全量预加载。Pillow缩放帧缓存最多32MiB、Tk图像缓存最多32MiB，另有原图和两帧交接缓冲。
- 管理窗口选择素材并输入回复文字；支持新增GIF/PNG/JPEG/WebP＋未压缩WAV。视频/其他音频需先转换；网页旧版仍保留其原有导入功能。
- 导入前用SQLite备份接口备份原库到`data/backups`，新素材生成新ID，不覆盖原素材。管理信息只在管理窗口显示。
- 数据库存储与旧播放器共用；关闭程序后修改/迁移整个player目录，保留data。不要用空库替换它。
- 桌面版默认本机接口为`http://127.0.0.1:8784/api/response`（用户指定，替代桌面版原8783），请求JSON格式同上级`接口说明.md`，调用方也须使用8784。当前已接入本地STT和服务器文字发送；已支持服务器返回回复文字和表情编号；有效结果驱动本地配套播放，普通通信确认不会当作模型回复。
- 该端口只为接口服务；图形界面完全在原生窗口中。旧网页版仍使用8783，不改动它；若桌面版的8784也被占用，先正常退出对应旧实例，或显式指定其他空闲端口。不会杀其他程序或自动改端口。

## 检查与排错

```sh
python3 player/desktop/app.py --check
sh player/desktop/start.sh --windowed
```

缺少图形显示环境时明确停止，请从Pi桌面启动；SSH终端通常没有桌面环境变量，不能在Windows本机执行后期待Pi显示。
无声时确认Pi输出设备/扬声器；ALSA错误会提示，不会操作麦克风或播放用户录音。
无root权限需求；不改其他队友文件、不设置自启、不修改系统音频/屏幕配置。

验证结果见`VALIDATION.json`。Windows上的真实窗口与素材解码检查不能替代Pi屏幕、音箱、触摸和帧率现场验收。

开发参考：[Python Tkinter](https://docs.python.org/3/library/tkinter.html)、[Pillow动态图像](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#gif)。

## 已集成的语音输入与服务器发送

Linux启动时自动寻找已有Sherpa离线安装（优先候选为同级stt及同一项目下offline-asr-upgrade-install-*/offline-asr-upgrade）。ASR模型选择来自本地asr-selection.json（缺省lite，另支持standard/Paraformer），自定义模型目录须完整存在，不会自动回退。找到多份运行环境或没有找到时明确提示，在底部“语音”里填写实际安装目录。不会下载模型或创建/覆盖虚拟环境，也不修改原独立识别程序。旧识别终端须先正常Ctrl+C退出，避免同一麦克风被占用。

- 本地lite模型、16kHz单声道PCM16、20ms采集请求，独立进程推理；最终句经JSON行管道交给软件。没有录音文件，也不把音频发出。
- **屏幕左上角动态条显示实际收音/发送/异常**；不默认展示用户转写。只有实际PCM到达且识别进程活跃时才动画。语音设置内可查看详细错误与样本统计。
- 源码默认服务器`127.0.0.1:9000`，请在“语音”核对实际服务器地址，默认口令文件是当前用户`~/zerotier_chat/.env`，对应已确认的Pi路径`~/zerotier_chat/.env`。只读ZT_CHAT_TOKEN，环境变量优先，不执行.env、不显示口令、不复制到源码或包中。需在既有ZeroTier连通环境运行。
- 沿用TCP UTF-8 JSONL，启用版本2就绪握手。认证且model_ready:true后开麦，只发送带end:true的非空最终句；accepted仅确认收到，result才驱动播放。服务器可在result.text返回包含meme_id/reply_text的JSON字符串，或在result直接返回同名字段。协议详见SERVER_PROTOCOL.md。
- 断线立即暂停收音并持续重连；最多一个待处理请求，保留原id。服务器启动标识相同则查询原请求状态，恢复最终结果；标识改变或unknown_request提示重说，不自动重发正文。收到result后播放完成再发送playback_done，回执保留到control_ack。
- “暂停收音”和退出会释放麦克风；没有检测到说完的半句话不强行补尾发送。已发送请求的确认状态仍按网络结果处理，不承诺断线送达。原模型/麦克风/网络现场性能仍需Pi验收。
- USB 录音设备掉线后停止本地音乐并等待设备重新出现；只重启本地识别进程，不重载服务器模型，不自动续播音乐。设备一直缺失时持续等待，不计失败次数；设备存在但恢复启动失败时最多尝试 5 次，按 1、2、4、8、8 秒退避。非设备故障不自动反复重启。手动暂停、关闭语音或退出会取消恢复，0.7 秒断句和八轮对话规则保持。
- USB 音频设备重连后，`audio_output.py` 按稳定的 USB sink 名称恢复同一个音箱为默认输出；解除意外静音，保留已有非零音量。音乐与表情配套声音都绑定这个输出，避免重连后声音转到板载输出。USB 未出现时等待；USB 硬件已出现但系统音频服务尚未枚举输出时，每次掉线恢复最多尝试重启一次当前用户的 WirePlumber，不反复重载音频服务或服务器模型。恢复验收同时检查音乐和表情声音的实际 sink 路由，不能只看识别已恢复。
- 语音设置保存到本机`data/speech-config.json`，只含路径/设备/IP/端口，不含口令。关闭设置后不显示管理信息。`--no-stt`仅播放；`--stt-root /实际ASR目录`可明确选择安装。

服务器推理接入沿用已有模型服务，新增就绪、收句确认、播放完成和断线恢复控制。等待推理与播放期间暂停收音；未实现唤醒词或声学回声消除。聆听期间仍连续采集PCM，不清空用户音频队列换速度。

嵌入运行核心在asr_runtime，来自本项目最新独立ASR的speech/audio/text_review；audio额外提供录音设备故障分类和子进程组配置，让设备失联触发恢复，退出超时可清理本软件自己创建的录音进程。该副本不改原ASR安装/模型/依赖。

服务器回复只含文字和表情编号，不接收服务器音频、不生成语音；本地原配声音内容不一定与回复文字相同。重复/过期回复不播，未知编号/错误格式在语音设置提示。

## 画面流畅度优化

- SQLite取媒体、GIF解码及缩放移到单个后台线程，Tk线程只提交现成图像；相同表情/尺寸重播复用缓存。
- 画布图像、字幕和底色复用，不再每帧清空重建；字幕仅在内容/尺寸改变时重排。暂停状态图标不反复重画。
- 图片按语音播放开始的单调时钟调度。界面落后时跳过过时的显示帧，不连续追赶；不会丢弃麦克风PCM或改动声音速度/素材时长。
- 新请求替换旧加载任务，切换/退出会取消过期结果；窗口缩放在后台重新适配，声音不因缩放重新播放。
- 语音设置的“画面提交/界面处理”是程序指标，**不是显示屏实测刷新率**。本地许多GIF约10帧/秒，不会凭空变成30/50帧；TFT若实际只刷新5Hz，仍需硬件队友核对驱动/接口。
- 若更新后仍卡，可在Pi桌面终端运行 `python3 desktop/diagnose_display.py --output display-diagnostics.json`（在player目录），只读现有驱动/桌面模式/降频信息，无额外安装，不改系统配置。SSH没有DISPLAY不代表屏幕故障。

主机缓存/调度检查通过，实际Pi STT并行负载和TFT流畅度需现场确认，不保证特定fps。

## 表情编号来源（当前规则）

原编号及声音从本地 `sucai_meme/meme_gif` 的 `meme-四位编号-名称.gif` 及同名 `.wav` 映射；画面只读取同级 `sucai_meme/meme_gif_background`。
服务器仍返回完整编号，例如 `meme-0004`。若本段背景为3，软件显示 `meme_gif_background/meme-0004-大笑秃头猫-3.gif`，声音仍播放 `meme_gif/meme-0004-大笑秃头猫.wav`，字幕使用reply_text。
不按列表顺序编号，不把CSV描述当指令，不从网络下载素材；旧SQLite内的同编号meme不再作为回退。

v2最终结果中的 `conversation_id` 标记服务器的真实对话。新编号首次到达时，在1～10内完整覆盖全部启用表情的背景组中随机选择一次；此后同一对话的所有表情、重播和手动meme播放都沿用该背景。允许相邻两段随机到同一背景。每段默认最多8个成功问答，第9条用户输入生成新对话编号并重新随机背景；真正等待用户空闲满10秒、显式重置也生成新编号，Pi不凭本地10秒或自行数轮猜测。欢迎画面先随机一个背景；新对话的首个有效服务器回复再确定该段背景。重连缓存结果保留原conversation_id，不因重连另选背景。

自动查找播放器/上两级目录中的 `sucai_meme/meme_gif`，也支持该范围内的 `meme-EmoStance/sucai_meme/meme_gif`。
当前Pi已观察到的来源为 `<repo>/sucai_meme/meme_gif`。
其他位置可启动时传 `--meme-dir /实际路径/sucai_meme/meme_gif`，用 `--check` 输出实际选用目录和可用数量。
`--meme-dir`指定原目录时，背景目录仍固定取其同级 `meme_gif_background`。目录缺失、重复编号、背景文件名不匹配或没有完整背景组会明确报错；不完整背景组不参与随机。播放时所选文件缺失不会换背景或回退原始无背景GIF。未知编号不播放；没有原目录同名WAV只显示带背景GIF，不借用旧库声音。
此前剔除的5个静音编号仍不启用。源目录始终只读，不移动/改名/删除队友文件。

原SQLite及新增user-编号素材保留；界面导入只写自己的数据库。目录映射模式不允许通过导入包覆盖meme编号。
GET /api/assets中目录素材时长为null（尚未后台加载）；后台扫描GIF数据块时长并读取WAV时长，至少播完一轮GIF及完整声音。
`--legacy-library`仅用于明确回退对照旧库，默认不会自动回退，不能与--meme-dir同时使用。

## 本地音乐模式

`meme_sing/` 提供“想听音乐”“放首歌”等本地意图、最近成功聊天情绪规则与文件名标签匹配、ffplay播放和语音停歌。默认素材目录为 `~/meme/meme-EmoStance/sucai_meme/meme_music`，用 `--music-dir` 可覆盖。文件名情绪后的数字是可选权重，末尾编号不当作唯一歌曲ID。

播放中说“停止”“停止音乐”“别放了”“不听了”结束音乐并恢复聊天。音乐阶段允许本地停止控制收音，临时识别只作停止检测，歌词不会发送给模型；未播放时普通“停止”仍走聊天。音乐与表情配套声音互斥，播放时不自动待机；自然结束或失败后恢复聊天，断线、关语音和退出应用会停歌。点歌不占服务器八轮计数，服务器的10秒空闲规则继续生效，较长歌曲后下一次聊天可能开启新对话。

## 小me语音待机与唤醒

服务器根目录的 `meme_huanxing/` 共享代码部署到本机同名包。说“小me，睡觉去吧”“小me，该睡觉了”进入待机；待机时说“小me，别睡了”“小me，别睡了，起床了”“小me，醒醒吧”唤醒。已清醒时唤醒语句走普通聊天，不重复起床。旧“去睡觉吧meme”兼容；命令必须有有限称呼，否定、引用、条件句、问句和他人转述不触发。

沿用安装目录中的 `sleep.gif` 和 `sleep.wav`，当前Pi路径为 `player/desktop/`。待机循环GIF第0～14帧；唤醒完整播放第15帧至结尾，最后一帧显示结束后才恢复普通收音。待机声音使用原WAV和同一个USB输出，唤醒开始时停止声音。触屏唤醒也播放完整动画。

待机中麦克风只做本地唤醒检测，其他语句不发模型；起床动画期间关麦，结束后才恢复聊天。睡觉/唤醒控制不占服务器八轮计数。音乐中说待机指令会先停歌；待机不会打断尚未结束的表情回复。保留20秒真正空闲时自动待机，讲话、推理和播放期间不计作空闲。

USB设备失联、服务器断线、关闭语音或退出会取消待机并停声；设备自动恢复后回到普通状态，重新选择USB音箱，不续播中断的待机或音乐。素材或播放异常会取消待机并提示错误。详细状态与验证见服务器仓库 `meme_huanxing/README.md`。

## 就绪后收音，回复播放结束后再开麦

1. 保留本地asr-selection.json所选profile/model/threads/silence_rms；没有配置时默认lite。start.sh使用0.7秒停顿、接口端口8784；后台已运行的旧参数须重启播放器才更新。Paraformer保留PCM能量静音端点及0.66秒编码尾部补齐，其他profile保留原识别器端点。只有完整端点句子才发送，不发送临时文字。
2. 本地模型可先加载，收到服务器版本2的model_ready:true后才开麦。出现非空临时识别或Paraformer检测到持续有效声音时发送speech_start；心跳与开启麦克风本身不作为用户活动。
3. 用户说完后worker关闭本轮采集，发送end:true整句。accepted保留等待状态，result验证后准备画面与声音；等待推理、准备、播放期间全程关麦，播放前核对采集关闭确认。
4. GIF一轮与aplay实际播放两项都完成后，发送playback_done；失败/取消发送playback_failed。等待250毫秒，再在服务器仍就绪时恢复收音。初始欢迎与手动播放同样暂停麦克风。
5. 断线暂停收音，保留已提交id；同服务器实例重连查询状态，重复result不重复播放。服务器重启或记录已过期则提示重说。手动/HTTP回复不能在服务器等待或播放中插队。
6. 未完整结束的句子不强制补尾；讲话超过25秒仍无端点时取消并提示重说。服务端收音租期30秒、播放租期120秒，避免控制消息丢失后永久占用。

本模式不存录音或用户转写，不上传音频。真实Pi须核对麦克风释放、字幕/表情、扬声器播放及完成后重新收音；主机协议或模拟测试不能代替现场验收。

按轮次关闭后管道中到达的样本仍单独计为gated_after_turn_samples，不混入下一轮。
