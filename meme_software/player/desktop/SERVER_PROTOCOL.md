# 服务器回复接入约定

客户端连接语音设置中指定的服务器（默认地址127.0.0.1是占位，端口9000），沿用现有 TCP UTF-8 JSONL、hello/hello_ok 认证、ping/pong；每帧末尾必须有换行，总大小最多1MiB。口令只用既有ZT_CHAT_TOKEN，不放进回复。

客户端每句最终识别发送：

```json
{"type":"request","id":"客户端生成的请求ID","text":"用户识别文字"}
```

## 推荐：不修改队友通信模块

现有 `ChatServer.on_text(text, client_name)` 返回字符串。算法层只需将以下对象用 `json.dumps(..., ensure_ascii=False)` 转为字符串后返回：

```json
{"meme_id":"meme-0157","reply_text":"听起来你今天很开心，我也替你开心！"}
```

现有模块会自动包成下列网络帧。`id`必须原样对应客户端request.id，别重新生成：

```json
{"type":"result","id":"客户端生成的请求ID","text":"{\"meme_id\":\"meme-0157\",\"reply_text\":\"听起来你今天很开心，我也替你开心！\"}"}
```

如果服务器本来就自行生成帧，也支持直接放字段：

```json
{"type":"result","id":"客户端生成的请求ID","meme_id":"meme-0157","reply_text":"听起来你今天很开心，我也替你开心！"}
```

服务器算法与实际回调由服务器队友接入；播放器更新不改队友communication源码，不代表服务器已经实现模型。

## 播放与异常

- meme_id必须是**本机已有素材完整编号**，reply_text为1～2000字非空文字。编号以本机8784接口GET /api/assets为准。已删除的编号也会拒绝，不猜编号、不自动导入。
- 收到有效回复后切换本地表情，播放该表情原配声音，回复文字在表情内底部。**服务器不传音频，播放器不生成语音**；本地原配声音的内容不保证等同服务器文字。
- 仅接受仍待确认的request.id对应result；重复/无关/超时ID和广播push不驱动播放。先收到新一句回复后，再到达的较早一句回复会忽略。新有效回复替换当前播放，不排成长队。
- 普通“服务器已收到…”保持通信确认，不换表情/字幕。JSON格式错误、缺字段或未知编号会在“语音”设置显示原因，原表情继续，不因服务端内容弹阻塞对话框。
- 服务器须在60秒内返回result。每个request只回一个最终result；不要先用同ID发回显确认、再异步补模型result，后者会被当重复。错误可回type=error/id/code/message。
- 沿用断线自动重连；断线句不排队、未确认不自动重发，重连后请重说。无额外HTTP下载/音频依赖。
- STT持续收音，尚无声学回声消除；扬声器播放可能回灌麦克风，应在Pi现场验证麦克风/扬声器布置。没有为回避问题而静默删除用户音频。

## 现场验收

先启动服务器监听及算法回调；Pi桌面运行desktop/start.sh。说一句话、停约1秒，核对服务端request.id/text、返回meme_id/reply_text、Pi画面和底部字幕/配套声音。界面“正在听”只代表收音状态，不代表算法回复正确。

主机本机模拟服务验证不能代替127.0.0.1真实服务或Pi扬声器/麦克风验收。
