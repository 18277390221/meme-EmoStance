# 小me语音待机与唤醒

服务器工作区的 `meme_huanxing/` 保存共享命令规则、待机状态控制和画面逻辑。部署工具把这个包安装到树莓派的 `player/desktop/meme_huanxing/`，无需另开服务器进程，也不更换推理模型。语音指令在树莓派本地处理。

## 使用

- 睡觉类：“小猫，睡觉吧”“小猫，睡觉。”“小猫，睡觉了。”“小me，睡觉吧。”进入本地待机，不发送模型。
- 起床类：待机时说“小猫，起床吧”“小猫，起床。”“小猫，起床了。”“小me，起床吧。”播放起床动画，完整结束后恢复聊天收音，不发送模型。
- 已经清醒时，唤醒语句仍走普通聊天，不重复播放起床动画。
- 已在待机时，睡觉类语句只继续本地待机收音，不会当成唤醒或发送模型。
- 正在播放音乐时说待机指令，先结束音乐，再进入待机；当前表情回复与配套声音完整结束后才进入待机。

称呼支持 `小猫`、`小me`、`小meme`、`meme` 和有限的常见识别同音“小咪”“小米”“小美”“小梅”“小妹”，兼容大小写、空格和句末标点，不扩展到“猫”或“小猫咪”。旧短句“小me，睡觉”“小me，起床”和长指令“小me，睡觉去吧”“去睡觉吧meme”“小me，起床了”“小me，别睡了，起床了”继续可用。单独说“睡觉”“起床”不作为本机控制命令；引用、条件句、否定和问句也不触发。

保留原有的20秒空闲自动待机：只在真正等待用户、语音与服务器就绪时计算；讲话、推理、表情播放和音乐播放期间不进入自动待机。

## 素材和状态

沿用树莓派安装后的素材，不复制或改名：

- 动画：`/home/aida/meme/meme-software/player/desktop/sleep.gif`
- 声音：`/home/aida/meme/meme-software/player/desktop/sleep.wav`

GIF帧号从0开始。待机循环播放第0～14帧；唤醒播放第15帧至最后一帧，等待最后一帧自身的显示时长后才结束。待机声音使用原 `sleep.wav`，输出沿用音乐和表情声音共用的USB音箱；唤醒开始时停止待机声音。触屏唤醒也经过相同的起床动画。

进入待机前先确认普通收音关闭，再打开只检测唤醒指令的本地识别窗口。待机中的其他话、睡觉和起床指令不发送模型，不推进服务端滚动上下文窗口或背景版本，不伪造表情播放回执。每个待机窗口携带独立标识，旧窗口迟到的事件不能唤醒新窗口。起床动画播放期间关闭麦克风，完整结束后按照原规则恢复普通收音。

USB音频设备失联、服务器断线、关闭语音或退出应用会取消待机并停止待机声音。USB自动恢复完成后回到普通状态，输出仍切回USB音箱；不恢复中断的音乐或待机动画。素材缺失、帧数不足或播放失败会明确取消待机，不把失败当作动画完成。

## 代码与验证

`commands.py` 提供无副作用的 `classify_command(text)`、`is_sleep_command(text)`、`is_wake_command(text)`。规则只返回意图，实际状态守卫在 `controller.py`；`screen.py` 负责GIF和声音。命令识别使用有限本地规则，不调用模型，也不宣称具有声学回声消除能力。

在服务器仓库根目录运行：

```bash
python -m unittest discover -s meme_huanxing/tests -v
python -m unittest model_information.tests.test_deploy_pi model_information_qwen.tests.test_deploy_pi -v
```

部署工具仅允许固定源码文件，默认源目录下没有包副本时从仓库根目录读取共享代码。只读检查不创建包目录；应用前完成所有校验，失败后仅撤回本次写入并尝试删除本次创建的空目录，保留其他文件、素材和已有配置。自动化规则及状态测试不能代替现场麦克风识别、USB扬声器和屏幕动画验收。
